# Mostly Free Staging Setup

This staging path is designed for launch-readiness practice without committing to the final production hosting plan.

## Target Shape

```text
Cloudflare DNS
  -> staging.yourdomain.com
  -> Render web service
  -> Neon staging Postgres
```

The Render service runs the API server and serves the built React app from the same origin. That keeps cookies, API calls, and Phase 39 smoke/load checks simple.

## 1. Neon Staging Database

Create a dedicated Neon project or branch for staging. Do not point staging at production data.

Required Render secret:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | Neon pooled or direct PostgreSQL connection string for the staging database |

Run migrations before accepting staging as healthy. The Render Blueprint includes:

```text
corepack pnpm run db:migrate
```

## 2. Render Web Service

Use the repository root `render.yaml` as a Render Blueprint. Render's dashboard will ask for values marked `sync: false`.

Required manual values:

| Key | Value |
| --- | --- |
| `APP_URL` | Final staging URL, for example `https://staging.yourdomain.com` |
| `DATABASE_URL` | Neon staging database URL |

Generated value:

| Key | Source |
| --- | --- |
| `SESSION_SECRET` | Generated by Render from `render.yaml` |
| `INTEGRATION_CREDENTIALS_KEY` | Generated by Render from `render.yaml` |
| `HEALTH_CHECK_TOKEN` | Generated by Render from `render.yaml` |

The service build command installs dependencies and builds both the API and frontend. The service start command runs the bundled API server, which serves `/api/*` plus the React app.

Leave live provider feature flags disabled until Phase 39 real-provider smoke testing is ready. Enable them one at a time with the matching provider credentials.

## 3. Cloudflare DNS

After the Render service exists, add the staging custom domain in Render first. Render will provide the DNS target.

In Cloudflare, create:

| Type | Name | Target | Proxy |
| --- | --- | --- | --- |
| `CNAME` | `staging` | Render's custom-domain target | DNS only for first validation |

After Render validates the custom domain and certificate, switch the Cloudflare record to proxied if desired. Set Cloudflare SSL/TLS mode to `Full (strict)`.

Do not use Flexible SSL for staging or production.

## 4. Phase 39 Evidence

When staging is live, run:

```powershell
$env:STAGING_BASE_URL="https://staging.yourdomain.com"
$env:HEALTH_CHECK_TOKEN="..."
corepack pnpm run staging:smoke-load
```

Attach the generated files from `artifacts/staging-launch/` to `docs/LAUNCH_READINESS.md` as launch sign-off evidence.

Also run the deployed health preflight:

```powershell
$env:NODE_ENV="production"
$env:DATABASE_URL="postgresql://..."
$env:SESSION_SECRET="..."
$env:INTEGRATION_CREDENTIALS_KEY="..."
$env:HEALTH_CHECK_TOKEN="..."
$env:PORT="3000"
$env:APP_URL="https://staging.yourdomain.com"
$env:PREFLIGHT_HEALTH_URL="https://staging.yourdomain.com/api/healthz/detailed"
corepack pnpm run deploy:preflight
```

Use real provider test credentials for the final Phase 39 smoke pass, not mock placeholders.
